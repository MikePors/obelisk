# Checks that mutation-check.sh will always report as SURVIVED, because a
# BROADER check catches the same cases first. Each is genuine redundancy, not
# a coverage gap -- no test can distinguish them, because disabling one still
# leaves the case refused.
#
# Format: <SourceFile.java>|<start of the call>   # why it is subsumed
#
# Keeping the redundant checks is deliberate: they give a more specific error
# message than the broad check would ("its body calls itself" beats "its body
# calls a method"), and they remain a safety net if the broader check is ever
# narrowed. But that means their protection is untestable today, and this file
# is the record of which ones and why.
#
# Adding an entry here should always be a considered decision. A NEW survivor
# that is not on this list fails the run -- that is the signal worth having.
#
# There are TWO kinds of entry here, and they are not equally comfortable:
#
#   (a) SUBSUMED -- a broader check refuses the same case first. Verifiable:
#       disable the broader one and the narrow one starts being reachable.
#
#   (b) BACKSTOP -- the check only fires when something UPSTREAM has already
#       failed, so with every precondition intact it is unreachable by
#       construction. No test can kill it by DISABLING it, because writing
#       one would mean anticipating the hazard -- and an anticipated hazard
#       gets a precondition instead.
#
#       This list used to add: "a backstop here is also UNVERIFIED. It could
#       be silently broken and nothing would notice." For the backstops that
#       guard a REPAIR, that is no longer true, and the correction is worth
#       stating plainly because the conclusion was wrong rather than merely
#       incomplete. Disabling the verifier is not the only mutation
#       available -- you can instead BREAK THE REPAIR IT GUARDS and require
#       the verifier to notice. tools/repair-mutation-check.sh does exactly
#       that, and the first run of it found TWO of these three verifying
#       something other than what they claimed: one checked the qualifier it
#       was HANDED rather than the one the repair emitted, and one proved a
#       repaired reference bound to the right declaration without checking
#       the reference was legal at all. Both passed a corrupted repair.
#
#       So: a backstop guarding a repair belongs in tools/repair-mutations.txt
#       and is verified there. A backstop guarding nothing in particular --
#       verifyBindingsPreserved's type comparison, verifyEverythingStillResolves
#       -- is still genuinely untested, and for those the old warning stands.
#
# This file is itself a hazard: an entry added on a plausible-sounding but
# WRONG justification converts a real signal into permanent silence. That has
# already happened once. RenameFieldRefactor|rejectShadowingCollision was
# listed here as "covered by rejectNewNameAlreadyBound", which was false --
# that check looks at the field's DECLARATION site, while this one looks at
# the enclosing scopes of every unqualified REFERENCE, where locals and
# parameters live. Disabling it silently changed a fixture's output from 15 to
# 10. Before adding an entry, disable the check and try to build a case that
# reaches only it.

InlineMethodRefactor.java|rejectSelfRecursion       # a self-call is a MethodCallExpr, banned by rejectMutatingOrCallExpressions
InlineMethodRefactor.java|rejectParameterWrites     # an assignment / ++ is banned by rejectMutatingOrCallExpressions
InlineMethodRefactor.java|rejectDeferredEvaluationConstructs  # lambda half: a lambda-valued body always fails rejectReturnTypeConversion, whose resolver cannot type a lambda. method-reference half: a bare `s::length` body is refused by rejectFreeReferences as a type reference
RenameMethodRefactor.java|rejectDuplicateSignature  # requires name AND matching parameter list on the owner's declared methods; rejectNewNameAlreadyVisible refuses on the bare name alone, against the same owners, so this is a strict subset

# --- (b) BACKSTOPS: unreachable while every precondition holds ---
InlineMethodRefactor.java|verifyBindingsPreserved   # post-transformation guard, unkillable by disabling it, but VERIFIED by fault injection -- tools/repair-mutations.txt skips the argument substitution and this catches it
InlineMethodRefactor.java|verifyEverythingStillResolves  # (a) SUBSUMED, and MEASURED as such: a repair emitting `__unresolvable__.SCALE` was caught by verifyBindingsPreserved's type resolution (line ~651), which runs first, so no corruption of a repair reaches the per-node half. It was previously listed as an untested backstop; it is a subsumed check
InlineMethodRefactor.java|verifyRepairsBindToOriginalDeclaration  # guards the static-field repair; unkillable by DISABLING it, but verified by fault injection -- tools/repair-mutations.txt drops the qualifier from the repair and this catches it
RenameMethodRefactor.java|verifyQualifiedCalls  # guards the qualify-shadowed-call repair; verified by fault injection in tools/repair-mutations.txt -- which is how it was caught checking the qualifier it was HANDED rather than the one emitted
RenameFieldRefactor.java|verifyShadowedReferences  # guards the escape-the-shadow repair; unreachable while the repair works, and verified by fault injection in tools/repair-mutations.txt -- which caught it comparing declarations without checking legality before it shipped
RenameClassRefactor.java|verifyQualifiedTypeReferences  # guards the qualify-the-reference repair; cross-file so structural rather than resolution-based, and verified by fault injection in tools/repair-mutations.txt -- which caught it checking only the sites the repair reported writing
ExtractVariableRefactor.java|verifyShadowedFieldReferences  # guards the escape-the-new-local repair; textual rather than resolution-based (this refactor splices source, it never mutates the AST), and verified by fault injection in tools/repair-mutations.txt -- which caught it accepting a bare name as a "qualified" form
ExtractMethodRefactor.java|verifyParametersBindToTheSameDeclarations  # guards the parameter-synthesis repair (#16); unreachable while the repair works, and verified by fault injection in tools/repair-mutations.txt -- which caught it comparing the result against the PLAN, the seventh verifier here to make that exact mistake
